# 글 작성 가이드

알고가요의 글은 `content/posts/<slug>.md` 파일 하나로 관리합니다. 파일을 추가하고 커밋하면 빌드 시 자동으로 목록, 카테고리, 사이트맵, RSS에 반영됩니다.

## 1. 새 글 만들기

1. `content/posts/` 에 `내-글-주소.md` 파일을 만듭니다. 파일 이름이 곧 URL(`/articles/내-글-주소`)이 되므로 **소문자 영문, 숫자, 하이픈만** 씁니다.
2. 아래 템플릿을 붙여 넣고 채웁니다.
3. 대표 이미지를 `assets/images-src/posts/내-글-주소.png` 에 넣고 `pnpm images` 를 실행합니다. `public/images/posts/내-글-주소.jpg` 가 생기면 frontmatter의 `image` 에 그 경로를 적습니다. 이미지가 아직 없으면 `image` 를 비워 두면 카테고리 기본 이미지가 쓰입니다.
4. `pnpm build` 로 검증합니다. 필수 항목이 빠지거나 형식이 틀리면 빌드가 파일 이름과 이유를 알려 주며 실패합니다.
5. 초안 상태로 커밋하려면 `draft: true` 를 둡니다. 개발 서버(`pnpm dev`)에서는 보이고 실제 배포에서는 제외됩니다. 게시할 때 `draft: false` 로 바꾸고 `publishedAt` 을 실제 게시일로 고칩니다.

## 2. 템플릿

```markdown
---
title: "글 제목 (40자 안팎, 무엇을 얻는지 드러나게)"
description: >-
  검색 결과와 카드에 보이는 한두 문장 요약. 40~160자.
category: living            # living(생활비) | digital(디지털) | travel(여행)
publishedAt: 2026-09-20     # 게시일 YYYY-MM-DD
# updatedAt: 2026-10-01     # 내용을 고친 날. 처음엔 생략
draft: true                 # 게시할 때 false
# image: /images/posts/내-글-주소.jpg   # 없으면 카테고리 기본 이미지
imageAlt: 이미지에 무엇이 보이는지 한 문장 (장면만 묘사, "사진"·"일러스트" 같은 매체 언급 금지)
summary:
  - 핵심 요약 첫 번째 문단. 결론을 먼저.
  - 두 번째 문단. 두세 문단이면 충분.
checklist:
  - 마치기 전에 확인할 항목
  - 4~6개
closing: >-
  마무리 한 문단. 오늘 당장 할 수 있는 한 가지를 제안.
---

## 첫 번째 소제목

본문. 소제목(`##`)마다 자동으로 1, 2, 3 번호가 붙고 목차가 만들어집니다. 그래서 소제목 텍스트에 `## 1. …`, `## 순서 1: …`처럼 번호를 직접 쓰면 "2. 1. …"처럼 두 번 붙습니다. 번호 없이 씁니다.

- 목록은 이렇게
- 항목 2

> **알아두세요** 주의할 점이나 조건은 인용문으로 쓰면 강조 박스가 됩니다.

| 표 제목 | 열 2 |
| --- | --- |
| 표도 쓸 수 있습니다 | 모바일에서는 가로 스크롤 |
```

`summary`, `checklist`, `closing` 은 선택 항목입니다. 글의 성격에 맞지 않으면 빼도 됩니다. 모든 글이 같은 구조면 오히려 기계적으로 보이니 표, 단계, 질문과 답처럼 구조를 바꿔 가며 씁니다.

## 3. 검증 규칙

빌드가 실패하는 조건입니다.

| 항목 | 규칙 |
| --- | --- |
| 파일 이름 | 소문자 영문·숫자·하이픈, 중복 불가 |
| title, description, category, publishedAt, imageAlt | 필수 |
| description | 40~160자 |
| category | living, digital, travel 중 하나 |
| 날짜 | YYYY-MM-DD, updatedAt은 publishedAt 이후 |
| image | `/images/` 아래 경로이고 `public/` 에 실제 파일이 있어야 함 |
| 본문 | `##` 소제목 1개 이상, 공백 제외 900자 이상 |

## 4. YAML에서 주의할 것

- 값에 `: ` (콜론+공백)이나 `#` 이 들어가면 따옴표로 감싸거나 `>-` 블록으로 씁니다. 한국어 문장에는 콜론이 자주 들어갑니다.
  ```yaml
  title: "가계부: 항목 5개로 시작하기"
  closing: >-
    긴 문장은 이렇게 들여 써서 여러 줄로 나눠도 한 문단으로 합쳐집니다.
  ```
- 날짜는 따옴표 없이 `2026-09-20` 형식으로 씁니다.
- 목록(`summary`, `checklist`)은 `  - ` 로 시작하는 줄로 씁니다.

## 5. 글의 톤

- 결론을 먼저 쓰고, 순서와 기준으로 설명합니다.
- 조건에 따라 달라지는 내용(요금, 제도, 보험, 안전)은 "확인하세요"로 끝내고 특정 상품·서비스를 추천하지 않습니다. 필요하면 `> **알아두세요**` 인용문으로 면책을 적습니다.
- ‘무조건’, ‘누구나’, ‘완벽하게’ 같은 표현을 피합니다.
- 공백 제외 1,800자 이상을 목표로 합니다. 소제목 4~6개, 소제목마다 2~3문단이면 자연스럽게 채워집니다.
- 자신이 직접 해 본 순서, 실제로 겪은 예외 하나를 넣으면 글이 달라집니다.

## 6. 게시 순서 (승인 심사 전)

1. 초안을 `draft: true` 로 커밋해 둡니다.
2. 3~4편씩 `draft: false` 로 바꾸고 `publishedAt` 을 그날 날짜로 고쳐 배포합니다. 열흘 안에 전부 게시하는 것을 목표로 합니다.
3. 배포 후 Search Console과 네이버 서치어드바이저에서 색인 요청을 합니다.
4. 20편이 모두 색인된 것을 확인한 뒤 AdSense 검토를 요청합니다.

## 7. 이미지

- 규격: 16:9, 1600×900 이상. GPT 이미지 생성은 1536×1024로 만들고 `pnpm images` 가 중앙을 잘라 맞춥니다.
- 프롬프트: `docs/image-prompts.md`
- 원본은 `assets/images-src/` 에 두고 git에는 올리지 않습니다(용량). 변환된 `public/images/**` 만 커밋합니다.
- `imageAlt` 에는 장면만 씁니다. "사진", "일러스트", "AI 생성" 같은 매체 언급은 넣지 않습니다.
